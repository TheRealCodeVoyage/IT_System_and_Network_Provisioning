## 1. SSH Key Generation and Configuration

SSH is the primary method for connecting to and managing remote servers. Generate a key pair now and set up a config entry — you'll reuse both next week when you launch your first AWS instance.

### Step 1.1: Generate an ed25519 Key Pair
```bash
ssh-keygen -t ed25519 -f ~/.ssh/my_aws_key -C "acit4640_aws"
```
Don't set a passphrase for this lab — press Enter twice when prompted.

### Step 1.2: Create an SSH Config File
An SSH config file makes managing multiple keys and servers much easier.
1. Create or edit `~/.ssh/config`:
   ```bash
   nano ~/.ssh/config
   ```
2. Add this template (you'll fill in the real IP address next week, once you have an AWS instance to connect to):
   ```text
   Host aws-instance
     HostName <IP_ADDRESS_HERE>
     User ubuntu
     PreferredAuthentications publickey
     IdentityFile ~/.ssh/my_aws_key
     StrictHostKeyChecking no
     UserKnownHostsFile /dev/null
   ```

## 2. Bash Scripting: Variables, Substitution, and Heredocs

Write a script that combines an environment variable, command substitution, and a heredoc — the three flipped-material topics from this week, in one working example.

### Step 2.1: Write the Script
```bash
nano ~/sys_report.sh
```

```bash
#!/usr/bin/env bash

# Command substitution: get current date and current user
TODAY=$(date +'%A, %B %d, %Y')
CURRENT_USER=$(whoami)

# Environment variable, defaulting to "Unknown" if not set
PROJECT_NAME=${PROJECT:-"Unknown Project"}

# Heredoc: generate a text file report
cat <<- EOF > ~/system_report.txt
	====================================
	System Report
	====================================
	Date: $TODAY
	Generated by: $CURRENT_USER
	Project: $PROJECT_NAME
	Current Directory: $PWD
	====================================
EOF

echo "Report generated at ~/system_report.txt"
```

### Step 2.2: Run It With an Environment Variable
```bash
chmod +x ~/sys_report.sh
export PROJECT="ACIT4640 Provisioning"
./sys_report.sh
cat ~/system_report.txt
```

## 3. Linux Service Management

Wrap the script in a systemd service so it can be run and monitored the same way a real background service would be.

### Step 3.1: Create a Service File
```bash
sudo nano /etc/systemd/system/sysreport.service
```

Replace `<YOUR_USERNAME>` with your actual Linux username (e.g. `iman` or `ubuntu`):
```ini
[Unit]
Description=Generate System Report
After=network.target

[Service]
Type=oneshot
User=<YOUR_USERNAME>
ExecStart=/home/<YOUR_USERNAME>/sys_report.sh

[Install]
WantedBy=multi-user.target
```
`Type=oneshot` tells systemd this service runs once and exits, rather than staying resident — appropriate for a script, not a long-running server process.

### Step 3.2: Manage the Service
```bash
sudo systemctl daemon-reload      # required after creating/editing a .service file
sudo systemctl start sysreport
sudo systemctl status sysreport
```
Confirm the report was regenerated by checking `~/system_report.txt`'s contents or modification time.
